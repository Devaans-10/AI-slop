# AI Slop Detector

A Python project for estimating whether a passage of text was written by a
human or generated by an AI. It fine-tunes a LoRA adapter on `bert-base-cased`
using Hugging Face, and it's built to run on Google Colab.

Unlike the single-domain original, this version:

- Handles texts longer than 512 tokens with overlapping windows.
- Reports a score for each paragraph, so you can see which part looks generated.
- Keeps human/AI pairs in the same split, so validation numbers aren't inflated.
- Reports accuracy per domain and per generator, not just one overall number.
- Lets you add data from other domains and generators with `--extra`.

## Project layout

```
slop/
  data.py           JSONL schema, pair-aware splitting, validation
  prepare_data.py   builds data/processed/ from the public Wikipedia dataset
  model.py          shared base model name and windowing
  train.py          LoRA fine-tuning and per-domain evaluation
  predict.py        scoring text with a trained adapter (CLI and function)
requirements.txt
```

## Data format

Every example is one JSON object per line:

```json
{"text": "...", "label": 1, "domain": "reddit", "source": "claude", "pair_id": "reddit-0042"}
```

- `label`: `0` = human, `1` = AI
- `domain`: where the text comes from (`wikipedia`, `reddit`, `fiction`, ...)
- `source`: who wrote it (`human`, or the generator name)
- `pair_id`: shared by a human text and its AI rewrite, so they stay in one split

## Generating AI essays

Use `slop/generate_ai_essays.py` to write AI-rewritten versions of human-written
essays with the Google Gemini API:

```bash
python -m slop.generate_ai_essays \
    --input human_essays.jsonl \
    --output data/processed/ai_essays.jsonl \
    --model gemini-2.5-flash
```

Input format (one JSON object per line; `label` and `source` are not needed):

```json
{"text": "...", "domain": "essay", "pair_id": "essay-0001"}
```

Each output row has `text` (the AI rewrite), `label: 1`, the same `domain`,
`source: "gemini"`, and the same `pair_id`. Set `GEMINI_API_KEY` before running;
the key is read from the environment and never stored in the repo.

Rows already in the output file are skipped by `pair_id`, so the script can
resume after a crash, and output is written one line at a time as each row
finishes. Pass the output file to `train.py` with `--extra` to add these AI
essays to the training set:

```bash
    python -m slop.train --train data/processed/train.jsonl \
        --val data/processed/val.jsonl --test data/processed/test.jsonl \
        --extra data/processed/ai_essays.jsonl

## Fetching an article

Use `slop/fetch_article.py` to pull the main text of a web article through the
TinyFish Fetch API. This is the first step of the "check any web article"
feature:

```bash
export TINYFISH_API_KEY="your_api_key_here"
python -m slop.fetch_article https://example.com/article
```

The script reads `TINYFISH_API_KEY` from the environment; never hardcode it. It
fetches the page with `format: "markdown"`, scopes extraction to `article` and
`main`, strips comments/nav/footer/header/newsletter/related-posts/aside, and
returns JSON with `url`, `title`, `paragraphs` and `word_count`. Articles with
fewer than 50 extracted words are rejected with a clear error.

## Evaluating honestly

Read `checkpoints/run1/metrics.json` after training. The `test_by_group`
section shows accuracy for each domain and generator. If accuracy is high for
Wikipedia and low for everything else, the model has learned Wikipedia style,
not AI writing in general. That is the failure the original project documented,
and it's the thing to fix before trusting the model.

## Improving it

In rough order of payoff:

1. **Add domains.** Collect human text from Reddit, fiction, news, and emails,
   and generate AI versions with several models. Save them with the schema
   above and pass them with `--extra`.
2. **Add generators.** Use models from several families. A detector trained on
   one generator tends to fail on the next one.
3. **Tune the threshold.** `THRESHOLD` in `slop/predict.py` is 0.5. Pick it on
   the validation set to hit the false-positive rate you can accept.
4. **Compare against a baseline.** A simple perplexity-based score shows whether
   the fine-tuned model is actually better.

## A note on use

Detectors like this make mistakes, and the mistakes are not spread evenly.
Writers whose English is non-native, and writers with very formal or
formulaic styles, are often flagged wrongly. Treat a score as a signal to look
more closely, not as proof that someone used AI. The output reports a score
and a per-paragraph breakdown for this reason.
